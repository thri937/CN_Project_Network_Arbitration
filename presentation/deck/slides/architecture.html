On each phone: join by code or QR, live limit, latency, and the explanation when cut

⇅ Wi-Fi hotspot · HTTP and WebSocket on port 8080

Slice gateway

The network: every byte passes through it. Enforces limits, measures every 2 s

⇅ Southbound API · 127.0.0.1:9090, secret token (phones can’t reach it)

Controller

Slices and devices, QR codes, scenarios, arbitration on/off, decisions

The controller decides; the gateway enforces and measures. Neither does the other’s job.

The testbed is four programs on one laptop. Each phone opens the department page, served by the gateway over the hotspot on port 8080; it joins a slice, starts a download at the rate it chooses, and sends small probes to measure latency. The slice gateway is the network: every byte the phones download passes through it, it enforces each slice’s limit and the shared 1 Mbps link, and it measures every two seconds. The controller is the brain: it reads those measurements over a private API on the laptop’s loopback address, protected by a secret token, so phones cannot reach it; it detects contention, runs the CBHA engine, pushes new limits back and records everything. The operator dashboard is where we watch it, show QR codes, run scenarios and read decisions.
