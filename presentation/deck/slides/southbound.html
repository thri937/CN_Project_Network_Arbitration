The controller and the gateway talk through one small API, the southbound API. The controller reads the last completed two-second window with GET stats; it is read-only, so the controller, the dashboard and the recorder all see exactly the same numbers. It sets a new limit with one PUT per slice, which the gateway applies on its next 20 millisecond tick. It sends the slice catalogue with the join codes, lists and removes devices, and the dashboard’s scenario buttons set every device’s demand through it. The API listens only on the laptop’s loopback address and needs a secret token, so a phone on the hotspot cannot change any limit. If the gateway restarts, the controller notices within three seconds and sends the catalogue again with the current limits.
